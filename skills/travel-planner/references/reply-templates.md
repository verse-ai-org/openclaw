# 回复格式模板

本文件供各步骤按需查阅，包含：小红书异常分流提示、路线框定回复格式、小红书链接展示规范。

---

## 第四步：xhs 明细抓取失败提示模板

当 `get-feed-detail` 失败/超时/返回空时，使用以下模板向用户发起分流确认：

```
当前小红书明细暂时无法抓取。你可以选择：

A. 你手动发我小红书笔记（我会按"用户提供证据"继续给路线候选）；

B. 我现在切换到搜索继续框定路线。
```

> 用户未明确选择 A 或 B 前，不得直接进入 `route-plan.mjs`。

---

## 第四步：路线框定回复格式规范

必须按以下顺序输出：

1. **平台与降级信息**：`used_platform`、`fallback_count`、`fallback_reason`
2. **小红书原文参考区块**（仅当 `used_platform = 小红书` 且有证据时）：见下方链接展示规范
3. **2-3 条候选路线**（带 `route_id`），每条 1 行权衡（时间成本 / 换乘压力 / 景观收益）
4. **推荐项**：指出推荐路线与推荐理由
5. **备选对比**：解释一条备选为何更弱
6. **住宿策略 + 交通策略**（简短）
7. **确认问题**：让用户选择 `route_id`

---

## 第四步：小红书链接展示规范

### 有链接时

```
小红书原文参考（优先展示）

- [帖子标题A](https://www.xiaohongshu.com/...)（点赞 1280，收藏 940）
- [帖子标题B](https://www.xiaohongshu.com/...)（点赞 860，收藏 610）
```

### 无有效链接时

```
本次未拿到可分享的小红书链接，请先登录或重试检索。
```

---

## 第八步：链接输出规范

- 若存在来源链接（航班 / 高铁 / 酒店 / 景点 / 参考帖子），必须用 Markdown 可点击格式输出。
- 若该条目无可分享链接，明确标注：`暂无可分享链接`。

---

## 平台降级提示规范

当发生平台降级时，必须在回复中显式提示：

- `xhs → search`：`已从小红书降级到搜索，原因：<fallback_reason>`
- 两平台都失败：仅返回「已尝试平台与失败原因」+「用户下一步动作」，不得给最终路线。

---

## 第六步：计划骨架总结卡片模板

必须先输出此卡片，再等用户确认，**不得与 Step 7 合并在同一回复里**。

1. **路线结论**：已选 `route_id` + 1 行推荐理由
2. **行程调研结论**：`go(可行) / caution（慎重） / block（不可行）` + 天气/交通关键提醒
3. **策略摘要**：交通策略（按需）+ 预算策略（按需）+ 住宿策略（按需）
4. **待确认项**：最多 2-3 条（如日期是否微调、是否接受某段长转场）
5. **确认问题**：`是否确认按该骨架进入每日详细计划？`

---

## 第七步：简要每日计划回复顺序

固定顺序输出：

1. 路线与节奏结论（1-2 行）
2. 简要每日计划（D1..Dn）
3. 天气与体力风险提醒
4. 进入 Step 8 的确认问题（是否开始筛选每日住宿与交通）

### 每日计划必含字段

每天必须包含以下全部字段：

- 当日主目标
- 当日次目标
- 核心活动区域/景点
- 建议时段（早/中/晚）
- 体力负荷（低/中/高）
- 天气风险提醒

---

## 第八步：最终答复顺序

必须按以下顺序输出（不可乱序、不可省略）：

1. 推荐结论
2. 交通与住宿策略（按天）
3. 正常详细每日计划（含执行卡片）
4. 预算拆分
5. 打包清单
6. 礼仪与安全提示
7. 行前待办

> 行前清单与打包清单内容细则见 `references/travel_guidelines.md`；礼仪提示见 `references/cultural_etiquette.md`。
