# Capability Matrix（工具可用性与降级策略）

本文件用于回答两个问题：
1) 当前通道/运行环境能不能用某个工具？
2) 不能用时如何降级，避免卡死或“偷偷继续”？

## 交互工具（Tool UI）

### `question_flow`

- **用途**：偏好采集、多步问卷
- **硬规则**：调用后必须 STOP，等待用户提交
- **降级**：若交互不可用 → 用自由文本提问（只问高影响项），并要求用户按“字段：值”逐行回答；随后从纯文本解析

### `option_list`

- **用途**：二选一/多选（平台选择、路线选择等）
- **硬规则**：调用后必须 STOP，等待用户点选
- **降级**：
  - 若 `option_list_allowed=false` 或通道不支持 → 发送“请回复选项 id（例如 route-a）”的文本版选择器
  - **不得**在用户未明确选择前进入下一步

### `approval_card`

- **用途**：关键确认（骨架确认、继续/调整）
- **硬规则**：必须用来确认关键步骤，不要只靠自由文本“你看行吗？”
- **降级**：通道不支持时 → 明确 ask：`请回复：确认 / 调整`；并在收到明确答复前 STOP

### `item_carousel`

- **用途**：路线图文卡片展示
- **降级**：若渲染不可用或缺图 → 退化为纯文本路线摘要（仍需提供 `route_id` 并完成选择流程）

## 外部数据工具（实时性来源）

### `flyai ...`

- **用途**：航班/高铁/酒店/POI 等实时查询
- **硬规则**：不得伪造价格/班次/库存/评分/链接；必须来自查询结果
- **降级**：
  - 查询失败 → 标注该项“未实时验证”，并避免给出具体价格/评分/可预订结论
  - 仍可继续产出“骨架/建议/决策点”，但必须显式提示缺失项

### `@skills/weather`

- **用途**：天气预报与风险判断
- **降级**：失败 → 天气标注“未验证”，`verdict` 至少降级为 `caution`

### `@skills/amap-lbs-skill`

- **用途**：驾车时长评估、路线可行性（尤其自驾场景）
- **降级**：失败 → 转场评估标注“未验证”；不要把不确定的时长当事实

### `@skills/xiaohongshu`

- **用途**：小红书证据拉取（search-feeds + get-feed-detail）
- **降级（强制交互）**：
  - detail 不可用 → 必须二选一确认：用户手动粘贴 / 切换到搜索（见 `workflows/step2-route-planning.md` 的 A-2-F）
  - 不得静默切换平台
