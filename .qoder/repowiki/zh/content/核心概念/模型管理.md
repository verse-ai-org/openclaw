## 简介

- 模型提供商的选择策略与认证路径
- 模型发现与目录构建机制
- 故障转移算法与冷却探测策略
- 模型配置的合并、验证与运行时注入
- 模型别名、认证标记与兼容性检查
- 模型选择优先级、负载均衡与性能监控
- **新增：MiniMax M2.7变体模型支持与配置**
- 配置示例、故障排查方法与最佳实践

## 核心组件
- 模型选择与别名解析：负责将用户输入解析为规范化模型引用，支持别名索引、允许列表与默认回退策略。
- 模型目录与发现：从本地models.json与SDK发现能力构建模型目录，并提供合成回退与输入类型标注。
- 故障转移与冷却探测：按优先级遍历候选模型，结合认证状态与冷却时间进行探测决策，记录失败原因并支持重试。
- 认证与密钥解析：统一解析环境变量、配置文件、OAuth令牌与AWS SDK链路，支持多配置文件与代理模式。
- **新增：MiniMax变体模型配置**：支持MiniMax M2.7标准版、高速版和Lightning三个变体的配置与管理。
- **新增：MiniMax OAuth插件**：提供MiniMax门户认证的OAuth流程，自动配置三个变体模型。
- **新增：MiniMax VLM图像理解**：支持MiniMax视觉语言模型的图像理解功能。
- 运行时配置注入：通过运行时快照与投影，确保配置变更在不重启情况下生效；同时支持会话与指令级别的覆盖。

## 详细组件分析

### 组件A：模型选择与别名解析
- 别名索引与键映射：通过别名到引用的映射表，支持以简短别名快速定位模型。
- 允许列表与键集合：基于配置的允许列表构建键集合，用于过滤候选集。
- 规范化与默认回退：对提供者ID与模型ID进行规范化处理；当未显式提供者时，采用默认提供者并发出兼容性警告。
- 允许模型集构建：允许任意模型或仅允许配置列表内的模型，并可将默认模型加入允许集。
- 模型引用解析：支持"提供者/模型"格式与纯模型别名两种输入方式。

### 组件C：故障转移与冷却探测
- 候选集构建：优先主模型，再追加配置的回退链；当请求提供者不同于配置主提供者时，仅保留已在链中的回退项。
- 冷却探测：当所有认证配置均处于冷却时，依据错误类型与冷却边界决定是否探测；对瞬时限流/过载场景允许单次探测。
- 失败记录与摘要：记录每次尝试的原因、状态码与错误消息，最终汇总失败摘要。
- 上下文溢出保护：对可能的上下文溢出错误直接抛出，避免错误转移导致更差结果。

```mermaid
flowchart TD
S(["开始"]) --> Build["构建候选集"]
Build --> Loop{"遍历候选"}
Loop --> |认证可用| TryRun["尝试运行"]
TryRun --> Ok{"成功?"}
Ok --> |是| Success["返回成功结果"]
Ok --> |否| Record["记录失败并继续"]
Loop --> |认证不可用| Cooldown["评估冷却与探测"]
Cooldown --> Probe{"允许探测?"}
Probe --> |是| TryRun
Probe --> |否| Skip["跳过并记录原因"]
Record --> Loop
Skip --> Loop
Loop --> |完成| Fail["抛出失败摘要"]
```

## MiniMax M2.7变体模型支持

### 变体概览
OpenClaw现已全面支持MiniMax M2.7系列的三个变体模型：

- **MiniMax M2.7**（标准版）
  - 适合一般编程和复杂任务处理
  - 默认reasoning设置：true
  - 成本：0.3/1.2（输入/输出，单位：美元/百万tokens）
  - 上下文窗口：200,000
  - 最大令牌：8,192

- **MiniMax M2.7 Highspeed**（高速版）
  - 专门优化的快速版本
  - 默认reasoning设置：true
  - 成本：0.3/1.2（输入/输出，单位：美元/百万tokens）
  - 上下文窗口：200,000
  - 最大令牌：8,192

- **MiniMax M2.7 Lightning**（Lightning版）
  - 最高性能版本
  - 默认reasoning设置：true
  - 成本：0.3/1.2（输入/输出，单位：美元/百万tokens）
  - 上下文窗口：200,000
  - 最大令牌：8,192

### OAuth认证流程
MiniMax提供两种认证方式：

1. **OAuth认证（推荐）**
   - 通过`minimax-portal-auth`插件实现
   - 支持全球和中国地区端点
   - 自动配置三个变体模型
   - 无API密钥要求

2. **API Key认证**
   - 适用于托管MiniMax服务
   - Anthropic兼容API端点
   - 需要MINIMAX_API_KEY环境变量

### 模型别名映射
- `minimax-m2.5` → `minimax-portal/MiniMax-M2.7`
- `minimax-m2.5-highspeed` → `minimax-portal/MiniMax-M2.7-highspeed`
- `minimax-m2.5-lightning` → `minimax-portal/MiniMax-M2.7-Lightning`

### 性能对比
- **处理速度**：Lightning > Highspeed > Standard
- **成本效益**：Standard/Lightning ≈ Highspeed（输入成本相同）
- **输出质量**：Lightning > Highspeed > Standard
- **适用场景**：
  - Lightning：实时交互、高频调用
  - Highspeed：平衡性能与成本
  - Standard：通用编程任务

## 性能考量
- 目录加载与动态导入：采用延迟导入与缓存策略，避免一次性依赖导致的阻塞与缓存污染。
- 并发写入与原子更新：models.json写入采用临时文件+原子重命名，配合写锁避免竞态。
- 冷却探测节流：限制探测频率与最大探测键数量，降低对上游的无效压力。
- 允许列表与别名索引：通过键集合与映射表减少重复解析成本。
- 运行时快照校验：仅在必要时重建快照，避免频繁深拷贝与序列化。
- **新增：MiniMax变体性能优化**：不同变体针对不同性能需求进行优化，Lightning版提供最高性能，Highspeed版平衡性能与成本，Standard版适合通用任务。

- 运行时快照与覆盖注入保障配置的即时生效
- 跨平台与跨运行时的一致性与安全性
