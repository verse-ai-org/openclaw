## 扩展系统概述
OpenClaw 使用扩展系统（也称为插件系统）来添加通道、AI 提供商、代理工具、CLI 命令、后台服务和生命周期钩子，而无需修改核心网关。所有内置通道（Telegram、Discord、WhatsApp、**WeChat** 等）和身份验证提供商（MiniMax、Qwen、Gemini 等）都是扩展本身。第三方扩展遵循完全相同的合约。

### 核心概念
- **两个清单文件**：每个扩展目录包含两个文件
  - `package.json`：npm 包描述符；`openclaw.extensions` 字段列出入口点
  - `openclaw.plugin.json`：运行时清单；声明 `id`、`configSchema`、可选的 `kind`、`channels`、`providers`
- **扩展来源优先级**：从四个位置发现扩展，当同一 `id` 出现在多个位置时，最高优先级的源获胜
- **扩展种类**：大多数扩展没有 `kind` 并可以自由共存，有两个种类是独占槽位
- **注册模型**：扩展在加载时同步注册，每个扩展接收 `OpenClawPluginApi` 实例并调用 `api.registerXxx()` 方法

## 扩展系统架构
扩展系统采用"SDK + 运行时"的双层架构，确保：
- SDK 层稳定、可发布、无副作用
- 运行时仅通过 api.runtime 注入，屏蔽内部实现细节
- 清单驱动的发现与校验，保障配置阶段的安全与一致性
- 扩展生命周期钩子贯穿消息收发、工具调用、会话与子代理、网关启停等关键节点

## 扩展生命周期钩子
扩展通过 `api.on(hookName, handler)` 注册类型化的生命周期钩子。钩子在代理、消息、工具、会话、子代理和网关生命周期的定义点触发。

### 安全策略
有两个钩子可以向系统提示注入内容，并受 `plugins.entries.<id>.hooks.allowPromptInjection` 控制：
- `before_prompt_build` - 当 `allowPromptInjection: false` 时完全阻止
- `before_agent_start` - 提示修改字段（`systemPrompt`、`prependContext` 等）被剥离；模型覆盖字段被保留

### 代理生命周期钩子
- `before_model_resolve` - 模型选择前，用于覆盖特定运行的模型或提供商
- `before_prompt_build` - 系统提示组装前，用于注入静态或动态上下文
- `before_agent_start` - 代理运行开始时（新代码推荐使用分离的两个钩子）
- `llm_input` - LLM 请求发送前（仅观察）
- `llm_output` - 收到LLM响应后（仅观察）
- `agent_end` - 代理运行完成时（成功或失败）

### 会话生命周期钩子
- `session_start` - 会话开始时
- `session_end` - 会话结束时

### 工具调用钩子
- `before_tool_call` - 工具调用前，返回 `params` 覆盖参数，或 `block: true` 阻止调用
- `after_tool_call` - 工具调用完成后（仅观察）
- `tool_result_persist` - 工具结果消息写入会话JSONL之前，返回修改后的 `message`
- `before_message_write` - **任何**消息写入JSONL之前，返回 `{ block: true }` 阻止持久化

### 消息生命周期钩子
- `message_received` - 来自任何通道的入站消息到达时
- `message_sending` - 出站消息发送前，返回 `{ cancel: true }` 抑制投递，或 `{ content: "..." }` 替换消息正文
- `message_sent` - 出站消息投递后（或失败）（仅观察）

### 子代理生命周期钩子
- `subagent_spawning` - 子代理即将创建时，返回 `{ status: "error", error: "..." }` 取消创建
- `subagent_delivery_target` - 允许扩展重定向子代理输出的交付目标
- `subagent_spawned` - 子代理进程启动后（仅观察）
- `subagent_ended` - 子代理完成、超时或被杀死时

### 网关生命周期钩子
- `gateway_start` - 网关HTTP服务器准备好接受连接时
- `gateway_stop` - 网关关闭时

## 扩展SDK API参考
每个扩展接收 `OpenClawPluginApi` 实例作为其 `register()` 函数的参数。API按扩展范围作用域化——所有注册都标记扩展的id以便诊断和所有权跟踪。

### 导入模式
每个扩展从其自己的SDK子路径导入，以保持依赖关系窄化：
```ts
import type { OpenClawPluginApi } from "openclaw/plugin-sdk/<extension-id>";
```

### api.registerTool()
注册一个代理工具（JSON Schema函数），LLM可以在代理运行期间调用。

### api.registerChannel()
注册一个消息通道（Telegram、Discord、WhatsApp、**WeChat** 等）。

### api.registerProvider()
注册一个具有一个或多个身份验证方法的AI提供商。

### api.registerService()
注册一个与网关生命周期绑定的后台服务（`start` / `stop`）。

### api.registerCommand()
注册一个斜杠命令（例如 `/phone arm`），在LLM代理之前处理且不消耗AI令牌。

### api.registerHook() / api.on()
两种注册生命周期钩子的方式：
```ts
// 推荐—类型安全，带编译时安全
api.on("before_model_resolve", (event, ctx) => {
  return { modelOverride: "claude-opus-4-5" };
});

// 传统—未类型的字符串事件
api.registerHook("before_model_resolve", handler, { name: "my-hook" });
```

### api.registerHttpRoute()
注册由网关内置HTTP服务器提供的HTTP路由。

### api.registerGatewayMethod()
在网关上注册自定义JSON-RPC方法。

### api.registerCli()
将子命令注入OpenClaw CLI。

### api.registerContextEngine()
注册一个上下文引擎实现。一次只能激活一个上下文引擎（独占槽位）。

### api.resolvePath()
解析用户提供的路径字符串（支持 `~` 扩展和相对路径）。

### 元数据字段
API对象还公开关于扩展的只读元数据：
- `api.id` - 扩展id
- `api.name` - 显示名称
- `api.version` - 来自清单的版本
- `api.description` - 来自清单的描述
- `api.source` - 入口文件的绝对路径
- `api.config` - 完整的网关配置
- `api.pluginConfig` - 扩展特定配置（`plugins.entries.<id>.config`）
- `api.runtime` - 运行时服务（工具、通道、状态、配置IO）
- `api.logger` - 作用域化日志记录器（`info`、`warn`、`error`、`debug`）

## 扩展加载机制
扩展在网关启动时由 `loadOpenClawPlugins()` 同步加载，流水线有九个阶段。

### 阶段概览
```
loadOpenClawPlugins()
        │
        ▼
[1] 发现扫描 4个源位置，收集候选[]
        │
        ▼
[2] 清单注册 为每个候选读取 openclaw.plugin.json
        │
        ▼
[3] 启用/禁用 应用允许/拒绝列表，内存槽策略
        │
        ▼
[4] Jiti初始化 懒创建jiti加载器与SDK别名映射
        │
        ▼
[5] 模块加载 jiti(source) — 直接运行.ts，无需构建步骤
        │
        ▼
[6] 导出解析 支持对象、函数和activate()导出
        │
        ▼
[7] 配置验证 使用JSON Schema验证plugins.entries[id].config
        │
        ▼
[8] API创建 createApi(record) — 每扩展隔离API
        │
        ▼
[9] register(api) 扩展初始化，调用api.registerXxx()
```

### 阶段1 — 发现
`discoverOpenClawPlugins()` 按优先级顺序扫描四个位置：
- `config` - `plugins.load.paths` 中的每个路径
- `workspace` - `<workspaceDir>/.openclaw/extensions/`
- `bundled` - 内部扩展目录（由 `OPENCLAW_BUNDLED_PLUGINS_DIR` 设置）
- `global` - `~/.openclaw/extensions/`

对于每个目录，扫描器读取 `package.json` 并查找 `openclaw.extensions` 以找到入口文件。如果该字段不存在，则回退到 `index.ts / index.js / index.mjs / index.cjs`。

**安全检查应用于每个候选：**
- 源文件路径不得逃逸插件根目录（符号链接遍历检查）
- 插件根和源路径不得是世界可写的（模式 & 0o002）
- 文件所有者UID必须匹配当前进程UID或root（非捆绑插件）
- 硬链接被拒绝（非捆绑插件）

### 阶段2 — 清单注册
`loadPluginManifestRegistry()` 为每个发现的候选读取 `openclaw.plugin.json` 并验证：
- `id` 字段存在且非空
- `configSchema` 字段是JSON对象

### 阶段3 — 启用/禁用决策
对于每个具有有效清单的候选，`resolveEffectiveEnableState()` 确定扩展是否应该加载：
1. **显式禁用**：`plugins.entries.<id>.enabled = false` → 禁用
2. **允许列表**：如果 `plugins.allow` 非空且扩展id不在其中 → 禁用（当 `channels.<id>.enabled = true` 时捆绑通道扩展自动启用）
3. **拒绝列表**：`plugins.deny` 包含该id → 禁用
4. **内存槽**：如果 `kind = "memory"` 且 `plugins.slots.memory` 命名了不同的扩展 → 禁用（快速路径，避免导入重型依赖）

### 阘段4 — Jiti加载器初始化
jiti加载器是**懒创建**的——如果所有扩展都被禁用（单元测试中的常见情况），则永远不会初始化。

当首次需要时，调用 `createJiti()` 与：
- `interopDefault: true` — 支持 `export default` 和 `module.exports`
- `extensions` — 接受所有TypeScript和JavaScript变体：`.ts`、`.tsx`、`.mts`、`.cts`、`.js`、`.mjs`、`.cjs`、`.json`
- `alias` — 将 `openclaw/plugin-sdk` 和每个子路径（例如 `openclaw/plugin-sdk/memory-core`）映射到磁盘上的实际文件

**SDK别名解析**沿加载器文件向上遍历目录树（最多6级），寻找：
- Loader运行于 `dist/` 或 `NODE_ENV=production` | `dist/plugin-sdk/<name>.js`
- Loader运行于 `src/` 开发环境 | `src/plugin-sdk/<name>.ts`

### 阶段5 — 模块加载
```ts
mod = getJiti()(safeSource);
```

jiti直接执行扩展的TypeScript源码——**扩展不需要构建步骤**。如果模块在导入时抛出异常，扩展被标记为 `error`，加载继续下一个扩展。

### 阶段6 — 导出解析
支持三种导出形状：
```ts
// 形状A — 标准对象与register()
export default {
  id: "my-ext",
  register(api) { ... },
};

// 形状B — 裸函数
export default function(api) { ... };

// 形状C — 传统别名
export default {
  activate(api) { ... },
};
```

### 阶段7 — 配置验证
扩展的 `configSchema`（来自 `openclaw.plugin.json`）用于验证来自用户配置文件的 `plugins.entries.<id>.config`。验证失败将扩展标记为 `error` 并记录模式错误。

### 阶段8 — API创建
`createApi(record, { config, pluginConfig })` 生成绑定到扩展记录的 `OpenClawPluginApi`。此API上的所有 `registerXxx()` 调用都写入共享的 `PluginRegistry`，标记为扩展的id，因此诊断和所有权始终可追踪。

网关 `runtime` 通过 `Proxy` 注入，因此只有当扩展实际访问运行时才物化运行时对象，保持简单扩展的启动速度。

### 阶段9 — register(api)
`register(api)` 同步调用。如果它返回 Promise，Promise将被**忽略**并发出 `warn` 诊断——不支持异步注册。

如果 `register` 抛出异常，扩展被标记为 `error`，记录错误，并继续加载下一个扩展。

### 缓存
加载的 `PluginRegistry` 以内存缓存，按键 `(workspaceDir, pluginsConfig)`。后续使用相同键的调用立即返回缓存的注册表并重新初始化全局钩子运行器。传递 `cache: false` 强制全新加载（测试和配置重载流程使用）。

## 扩展已知限制
本文档记录了扩展系统的已知陷阱和设计约束。理解这些可以避免难以调试的静默失败。

### 不支持异步 `register()`
**最常见的静默失败来源。**

`register(api)` 同步调用。如果它返回 `Promise`，Promise将被**丢弃**并发出 `warn` 级诊断，然后继续执行。`api.registerXxx()` 调用在启动过程中与网关竞争——实际上总是失败：注册永远不会生效。

```ts
// 错误—register返回Promise；工具从未注册
export default {
  id: "my-ext",
  async register(api) {
    const data = await fetch("https://api.example.com/config").then((r) => r.json());
    api.registerTool(buildTool(data));  // 启动时永远无法到达
  },
};
```

```ts
// 正确—register是同步的；异步工作移动到服务
export default {
  id: "my-ext",
  register(api) {
    // 同步注册工具与静态定义。
    api.registerTool(myTool);

    // 将异步初始化推迟到服务。
    api.registerService({
      id: "my-ext-init",
      start: async (_ctx) => {
        const data = await fetch("https://api.example.com/config").then((r) => r.json());
        // 在工具调用时存储结果供工具读取。
      },
      stop: async (_ctx) => {},
    });
  },
};
```

如果在 `openclaw plugins status --deep` 中看到类似 `"my-ext: register() returned a Promise; async registration is not supported"` 的 `warn` 诊断，这就是原因。

### Jiti直接执行TypeScript—无需构建步骤，但有折衷
加载器使用 [jiti](https://github.com/unjs/jiti) 直接运行 `.ts` 源码，无需预构建步骤。这对开发很便利，但有影响：

#### 动态导入混合
不要在同一扩展文件中混合使用 `await import("x")` 和 `import ... from "x"`。当jiti转换文件时，两种导入风格可能解析到不同的模块实例，导致类型不匹配、双重初始化或运行时错误。

如果需要延迟加载，将它隔离在专用的 `*.runtime.ts` 边界文件中并动态导入该边界：
```ts
// my-ext/heavy.runtime.ts
export { heavyLib } from "heavy-lib";   // 仅在此处使用静态导入

// my-ext/index.ts
export default {
  id: "my-ext",
  register(api) {
    api.registerService({
      id: "my-ext-heavy",
      start: async (_ctx) => {
        const { heavyLib } = await import("./heavy.runtime.js");
        heavyLib.init();
      },
      stop: async (_ctx) => {},
    });
  },
};
```

重构任何触及延迟加载边界的代码后，运行 `pnpm build` 并检查 `[INEFFECTIVE_DYNAMIC_IMPORT]` 警告。

#### jiti不支持的TypeScript特性
jiti使用esbuild剥离类型并支持大多数TypeScript语法。以下特性**不支持**或行为不同：
- `const enum` — 使用常规 `enum` 或纯对象字面量
- 在 `tsconfig.json` `paths` 中定义的路径别名 — 仅加载器注入 `openclaw/plugin-sdk/*` 别名。其他路径别名（例如 `@/foo`）不会解析
- `emitDecoratorMetadata` — 不支持
- 某些仅 `.d.ts` 类型导入与 `import type ... assert { type: "json" }` 语法

#### 堆栈跟踪中的源映射
当扩展抛出错误时，jiti的源映射用于指向原始 `.ts` 文件。堆栈跟踪通常准确，但在具有复杂宏或条件编译的文件中行号可能偏移。

### 安全检查拒绝某些文件布局
发现阶段对每个候选应用安全检查。失败的扩展会被静默跳过（发出 `warn` 诊断）并且永远不会到达 `register()`。

| 检查 | 原因 | 修复 |
|---|---|---|
| 世界可写路径 | 扩展目录或源文件具有 `o+w` 权限（模式 & 0o002） | `chmod o-w <dir>` |
| UID不匹配 | 文件所有者UID不匹配当前进程UID（非捆绑仅） | 确保文件由运行网关的用户拥有 |
| 硬链接被拒绝 | 源文件是硬链接（非捆绑仅） | 使用普通文件或符号链接 |
| 路径遍历 | 源路径通过符号链接逃逸插件根 | 解析符号链接使其保持在插件目录内 |
| 备份目录 | 目录名称匹配 `*.bak`、`*.backup-*` 或 `*.disabled` | 重命名目录 |

运行 `openclaw plugins status --deep` 查看哪个检查失败。

### 缺少 `openclaw.plugin.json` 或无效
`openclaw.plugin.json` 是必需的且必须有效。缺少、无法解析或结构无效的清单会在清单阶段阻止扩展加载——模块文件从未被导入。验证器检查：
- `id` 字段：存在且非空字符串
- `configSchema` 字段：存在且为JSON对象

其他字段（`name`、`description`、`kind`、`uiHints`）是可选的。

### 独占槽位：内存和上下文引擎
一次只能激活**一个** `"kind": "memory"` 和一个 `"kind": "context-engine"` 的扩展。活跃扩展由以下配置选择：
```json5
{
  plugins: {
    slots: {
      memory: "memory-lancedb",       // 默认："memory-core"
      contextEngine: "my-context-engine",
    },
  },
}
```

所有其他具有相同 `kind` 的扩展在第3阶段（模块加载之前）被禁用，状态为 `disabled`，原因是 `"memory slot taken by <id>"`。这是有意为之，不是错误。

### 配置验证在加载时拒绝
如果 `plugins.entries.<id>.config` 不满足 `openclaw.plugin.json` 中声明的 `configSchema`，扩展被标记为 `error` 且不调用 `register()`。仔细检查模式——特别是 `additionalProperties: false`，它会拒绝未知键。

### 注册表缓存按配置快照键控
加载的 `PluginRegistry` 以内存缓存，按键 `(workspaceDir, pluginsConfig)`。如果在磁盘上更改配置文件，必须重启网关才能使新配置生效。传递 `cache: false` 给内部加载器API会绕过缓存（测试和配置重载流程使用）。

### `api.registerHttpHandler()` 已删除
旧的 `api.registerHttpHandler(...)` API已被删除。如果扩展调用它，加载器捕获 `TypeError` 并记录诊断：
```
deprecated api.registerHttpHandler(...) was removed; use api.registerHttpRoute(...) for
plugin-owned routes or registerPluginHttpRoute(...) for dynamic lifecycle routes
```

将所有使用替换为 `api.registerHttpRoute()`。

### 禁止原型变异
根据项目编码风格，扩展**不得**通过原型变异共享行为（`Class.prototype.method = ...`、`Object.defineProperty` 到 `.prototype`）。依赖原型修补的扩展将失败类型检查和代码审查。

### 扩展不能在 `dependencies` 中使用 `workspace:*`
当OpenClaw安装第三方插件时，它在插件目录内运行 `npm install --omit=dev`。pnpm `workspace:*` 规范不受普通npm理解，导致安装失败。将 `openclaw` 放在 `devDependencies` 或 `peerDependencies` 中。

### `register()` 抛出对其他扩展是非致命的
如果 `register()` 抛出，扩展被标记为 `error`，加载继续下一个扩展。单个坏扩展不会阻止其余扩展加载。检查 `openclaw plugins status` 确认所有预期扩展的状态为 `loaded`。

### 服务器端插件HTTP路由处理

#### HTTP路由注册与匹配
```typescript
export function createGatewayPluginRequestHandler(params: {
  registry: PluginRegistry;
  log: SubsystemLogger;
}): PluginHttpRequestHandler {
  const { registry, log } = params;
  return async (req, res, providedPathContext, dispatchContext) => {
    const routes = registry.httpRoutes ?? [];
    if (routes.length === 0) {
      return false;
    }

    const pathContext = providedPathContext ?? 
      resolvePluginRoutePathContext(new URL(req.url ?? "/", "http://localhost").pathname);
    const matchedRoutes = findMatchingPluginHttpRoutes(registry, pathContext);
    
    // 检查认证要求
    if (matchedRoutesRequireGatewayAuth(matchedRoutes) && 
        dispatchContext?.gatewayAuthSatisfied === false) {
      log.warn(`plugin http route blocked without gateway auth (${pathContext.canonicalPath})`);
      return false;
    }

    // 处理匹配的路由
    for (const route of matchedRoutes) {
      try {
        const handled = await route.handler(req, res);
        if (handled !== false) {
          return true;
        }
      } catch (err) {
        log.warn(`plugin http route failed (${route.pluginId ?? "unknown"}): ${String(err)}`);
        if (!res.headersSent) {
          res.statusCode = 500;
          res.setHeader("Content-Type", "text/plain; charset=utf-8");
          res.end("Internal Server Error");
        }
        return true;
      }
    }
    return false;
  };
};
```

export async function installPluginFromPath(
  params: {
    path: string;
  } & PackageInstallCommonParams,
): Promise<InstallPluginResult> {
  const pathResult = await resolveExistingInstallPath(params.path);
  if (!pathResult.ok) {
    return pathResult;
  }
  const { resolvedPath: resolved, stat } = pathResult;
  const packageInstallOptions = pickPackageInstallCommonParams(params);

}

## 性能考量
- 运行时方法映射到现有核心实现，避免重复逻辑与开销。
- 文本分块、媒体处理、TTS/STT、入站防抖等能力在运行时中复用，减少扩展自实现成本。

## 故障排查指南
- 清单与配置错误：检查 openclaw.plugin.json 的 id 与 configSchema 是否存在且合法；未知键或未声明的频道/提供商/技能会导致校验失败。
- 运行时访问异常：若 api.runtime 未正确注入或运行时未初始化，需确认扩展是否遵循 SDK/运行时契约。
- 安全边界：扩展被视为可信组件，安装/启用即授予与本地代码相同的信任级别，应关注边界绕过问题（如未认证加载、白名单/策略绕过、沙箱/路径安全绕过）。
