## 简介
本文件面向OpenClaw网关的RPC方法，系统性梳理其核心能力与调用方式，覆盖健康检查、配置管理、会话控制、节点操作等关键功能，并按"基础方法、通道方法、插件方法"进行分类说明。文档同时给出调用示例、最佳实践与性能建议，帮助开发者与运维人员高效、安全地集成与使用网关。

**更新** 新增Profile解析方法(profile.parse)，集成文件处理能力和AI分析功能，支持从文本、URL和文件中提取用户画像信息。

## 项目结构

- 文档与参考：官方RPC规范、网关健康、配置、配对、认证、心跳等主题文档。

## 详细组件分析

### CLI RPC 客户端
- 功能要点
  - 选项：URL、令牌、超时、是否等待最终响应、JSON输出模式。
  - 行为：根据是否JSON模式决定是否显示进度条；统一透传到通用调用器。
  - 客户端标识：记录客户端名称与模式，便于网关侧审计与统计。
- 参数与返回
  - 输入：方法名、选项对象、可选参数、额外控制（如是否等待最终响应、是否显示进度）。
  - 输出：RPC调用结果，支持流式分片与最终聚合。
- 权限与安全
  - 令牌通过环境变量注入，避免命令行参数泄露；建议仅在受信环境中使用。
- 最佳实践
  - 明确设置超时，避免长时间阻塞。
  - 在自动化场景中启用JSON输出，便于解析。
  - 使用"等待最终响应"选项获取完整结果（适用于需要聚合的长流程）。

### 方法分类与调用示例

#### 基础方法
- 健康检查
  - 用途：确认网关运行状态与可达性。
  - 调用方式：通过CLI或任意RPC客户端向网关发送健康检查方法。
  - 参数：无或极简。
  - 返回：状态码与简要信息。
  - 权限：通常无需认证。
  - 参考：见官方健康检查文档。
- 系统状态
  - 用途：查询网关版本、运行时间、资源占用等。
  - 调用方式：CLI或HTTP/WebSocket均可。
  - 权限：视部署策略而定，常见为管理员或受信范围。
- 配置读取/写入
  - 用途：读取或更新网关配置（如端口、令牌、通道与插件配置）。
  - 调用方式：CLI或RPC客户端。
  - 权限：仅允许受信账户或管理员。
  - 参考：见官方配置文档。
- **Profile解析方法**
  - 用途：解析用户提供的文本、URL和文件，提取结构化用户画像信息。
  - 调用方式：通过网关RPC方法调用profile.parse。
  - 参数：text（可选字符串）、urls（可选字符串数组）、files（可选文件数组）。
  - 返回：userMdContent（结构化用户信息）、memoryContent（补充背景信息）、skippedUrls（跳过的URL列表）、skippedFiles（跳过的文件列表）。
  - 权限：需要有效的API密钥和可用的默认模型配置。
  - 功能特性：支持.md、.doc、.docx、.pdf文件解析，URL内容抓取，AI模型分析。

### Profile解析方法详细说明

#### 功能概述
Profile解析方法(profile.parse)是OpenClaw新增的核心功能，旨在帮助用户快速构建AI代理的用户画像。该方法能够处理多种输入源，包括用户直接输入的文本、网页URL链接，以及本地文件上传，通过AI模型分析提取结构化的用户信息和补充背景内容。

#### 支持的输入格式
- **文本输入**：用户直接输入的描述性文本
- **URL链接**：支持网页内容抓取，最长15秒超时
- **文件上传**：支持.md、.doc、.docx、.pdf四种格式
  - .md文件：直接读取UTF-8文本内容
  - .doc/.docx文件：使用mammoth库提取纯文本
  - .pdf文件：使用pdf-parse库提取文本内容

#### AI分析与输出
方法使用网关配置的默认AI模型进行内容分析，输出格式严格遵循预设的XML标签结构：

```xml
<USER_MD>
- **Name**: [姓名或省略]
- **Role**: [职业或省略]
- **Domains**: [领域1, 领域2, ... 或省略]
- **Tools**: [工具1, 工具2, ... 或省略]
- **Preferences**: [偏好1, 偏好2, ... 或省略]
</USER_MD>
<MEMORY_MD>
[格式良好的Markdown内容，包含标题和结构，或空内容]
</MEMORY_MD>
```

#### 配置与限制
- **文件上传限制**：默认最多5个文件，单个文件最大5MB，可通过配置调整
- **URL抓取超时**：15秒超时，失败的URL会被记录在skippedUrls中
- **AI分析超时**：60秒超时，防止长时间阻塞
- **API密钥要求**：需要有效的API密钥和可用的默认模型配置

#### 错误处理
方法提供了完善的错误处理机制：
- 参数验证：确保至少有一个有效输入源
- 文件大小验证：超过限制的文件会被跳过
- 文件类型验证：不支持的文件类型会被跳过
- URL抓取失败：网络错误或内容无效的URL会被跳过
- AI分析失败：模型不可用或返回无效内容时返回相应错误

## 性能考量
- 超时设置：为所有RPC调用配置合理超时，避免长时间阻塞导致资源浪费。
- 流式响应：对于长耗时任务，优先采用流式分片返回，前端可渐进渲染。
- 并发控制：限制并发RPC数量，避免网关过载。
- 缓存与复用：对频繁访问的配置与元数据进行缓存，减少重复请求。
- 端口与网络：本地回环端口具备低延迟优势；跨网络调用应考虑TLS与代理配置。
- **Profile解析优化**：合理设置文件上传限制，避免大文件影响性能；网络抓取设置合适的超时时间。

**更新** Profile解析方法具有特定的性能考量，包括文件大小限制、URL抓取超时和AI分析超时，这些都需要在配置中合理设置以平衡性能和功能需求。

## 故障排查指南
- 启动失败
  - 检查Node版本与OpenClaw入口路径解析是否正确。
  - 查看子进程标准输出/错误日志，定位异常。
- 无法就绪
  - 确认端口未被占用；使用"强制覆盖"策略或更换端口。
  - 观察就绪轮询日志，关注HTTP状态码。
- 认证失败
  - 确认令牌已正确注入环境变量且未被截断。
  - 检查令牌有效期与作用域。
- 健康检查异常
  - 使用官方健康检查文档核对期望行为与返回格式。
- 通道/插件问题
  - 根据对应通道或插件文档排查权限与配置。
- **Profile解析问题**
  - 检查API密钥配置和默认模型设置。
  - 验证文件格式和大小限制。
  - 确认网络连接和URL可达性。
  - 查看skippedUrls和skippedFiles列表了解失败原因。
